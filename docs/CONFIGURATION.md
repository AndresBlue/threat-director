# Threat Director 2.0 Configuration Guide

Threat Director generates its documented configuration at:

```text
config/threatdirector.json5
```

JSON5 preserves ordinary JSON values while allowing comments. Every property generated by Threat
Director has an English explanation immediately above it.

## Quick start: choose an experience

The three most important switches are `general.enabled`, `vanilla.enabled`, and `modded.enabled`.
Do not delete disabled sections; keeping them preserves your tuning for later use.


| Result                                              | `general.enabled` | `vanilla.enabled` | `modded.enabled` |
| --------------------------------------------------- | ----------------- | ----------------- | ---------------- |
| No Threat Director gameplay                         | `false`           | any               | any              |
| Vanilla-like server AI only                         | `true`            | `true`            | `false`          |
| Extraordinary abilities without Director encounters | `true`            | `false`           | `true`           |
| Complete experience                                 | `true`            | `true`            | `true`           |


Vanilla-only is recommended when the administrator wants smarter pressure without changing baseline
mob attacks or requiring client installation. The complete experience still accepts unmodded clients
because it registers no gameplay content; only HUD rendering requires the client JAR.

After editing the file, run:

```text
/threatdirector debug config reload
```

Reloading is transactional. If a property is missing, unknown, malformed, or violates a safety
relationship, the entire candidate is rejected and the last known-good snapshot remains active.

## File conventions

- Probabilities use decimals: `0.25` means 25%.
- Minecraft runs at 20 ticks per second; `200` ticks equals 10 seconds.
- Distances and radius are measured in blocks.
- Vanilla effect amplifiers are zero-based: `0` means level I, `1` means level II, and `-1`
disables effects in fields that allow it.
- Identifiers use `namespace:path`, such as `minecraft:zombie`.
- Keep `schemaVersion: 4`; Threat Director owns schema evolution.
- Do not remove properties or invent names. The strict reader reports both cases.

The file exposes every gameplay module, public behavior, probability, range, duration, and balance
curve. Internal implementation invariants—attribute UUIDs, numerical tolerances, anti-loop scan
batches, and ownership bookkeeping—remain fixed so a syntactically valid file cannot corrupt entity
persistence or stall the server thread.

## 1. `general`



### `general.enabled`

This is the absolute gameplay switch. Setting it to `false` releases active encounters, clears the
HUD, and makes entity extensions inert while preserving all configured values.

### `general.intensity`

This section controls the per-player 0–100 threat calculation.


| Options                                                                                | Purpose                                                                                                 |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `sampleIntervalTicks`, `smoothingAlpha`, `hysteresisPoints`                            | Sampling frequency and stability. Higher alpha reacts faster; higher hysteresis prevents band flapping. |
| `maxIntensity`, `activationThreat`                                                     | Global ceiling and the point where targeting and abilities begin scaling.                               |
| `minimumHealthRatio`, `recentDamageWindowTicks`, `recentDeathCooldownTicks`            | Relief for injured or recently killed players.                                                          |
| `defenseCap`, `offenseCap`, `sustainCap`, `groupCap`, `contextCap`, `stressPenaltyCap` | Maximum contribution from each signal family. Positive caps may not exceed `maxIntensity` in total.     |
| `playTimeHoursForMaximum`, `experienceLevelForMaximum`                                 | Progression pace for time and XP pressure.                                                              |
| `deathPlayTimePenalty`, `maximumDeathPlayTimePenalty`                                  | Partial playtime-pressure recovery after death and its accumulated cap.                                 |


Threat is never blindly copied between players. Equipment, health, XP, playtime, environment, and
distress remain individual. Group scaling only applies when eligible players are near the same
encounter.

### `general.performance`

- `workBudgetMicrosPerTick` and `maxPlannerOperationsPerTick` bound planner work.
- `degradeAfterTicks` requires sustained load before reducing quality.
- `recoverAfterTicks` requires sustained stability before recovery.
- `level1TickTimeMs` through `level6TickTimeMs` must be strictly increasing.

As the governor rises, it reduces decision frequency, candidate counts, pathfinding, and new
encounter admission. Raising these limits may increase visible intensity but also server MSPT.

### `general.telemetry`


| Option                            | Effect                                                                                              |
| --------------------------------- | --------------------------------------------------------------------------------------------------- |
| `enabled`                         | Writes local NDJSON telemetry inside the world save. Changing the writer requires a server restart. |
| `operatorChatLoggingEnabled`      | Allows or blocks `/threatdirector logging` for OP players.                                          |
| `queueCapacity`, `flushBatchSize` | Maximum queue and write batch; the batch cannot exceed the queue.                                   |
| `includePlayerUuid`               | Includes UUIDs in local telemetry. Consider privacy before enabling it.                             |


Chat logging is session-only, OP-only, and independent from disk telemetry.

### `general.integrations`

`enableExternalAdapters` loads compatible optional providers at server startup. Keep it disabled for
the most conservative compatibility profile. Changing it requires a restart because providers load
transactionally once per runtime.

## 2. `vanilla`

This category contains behavior that remains completely understandable to vanilla clients.

### Master switches

- `enabled`: enables the category.
- `adaptiveDirectorEnabled`: allows automatic encounters based on threat and environment.
- `enhancedTargetingEnabled`: extends detection and aggro without enabling special arrows, traits,
hatchlings, fuse changes, or other modded abilities.

OP commands can still inspect threat while automatic Director behavior is disabled.

### `vanilla.director`

- `scanIntervalTicks`: interval between automatic candidate scans.
- `minimumIntensity`: minimum threat for automatic activation.
- `encounterChancePerScan`: chance per eligible scan.
- `cooldownMinTicks` / `cooldownMaxTicks`: random relief window after an encounter.
- `requireNightOrDarkness`: requires a dangerous environmental context.
- `allowedDimensions`: explicit dimension allowlist.



### `vanilla.encounter`


| Group       | Options                                                                                                              |
| ----------- | -------------------------------------------------------------------------------------------------------------------- |
| Population  | `minMobs`, `maxMobs`, `hardMaxMobs`, `maxNearbyHostiles`, `maxActiveEncounters`                                      |
| Source      | `recruitNaturalMobs`, `directedSpawning`, `allowDirectorSpawnedCreepers`                                             |
| Space       | `recruitRadius`, `spawnMinDistance`, `spawnMaxDistance`, `maxPursuitDistance`                                        |
| Phases      | `stalkingMinTicks`, `stalkingMaxTicks`, `positioningMaxTicks`, `engagingMaxTicks`, `reliefTicks`, `contactLossTicks` |
| Composition | `allowedMobIds`, `threatCosts`                                                                                       |


Natural loaded mobs are recruited first when enabled. Directed vanilla spawning only fills a deficit.
`hardMaxMobs` is validated to an absolute ceiling of 128, and `maxNearbyHostiles` must cover at least
the ordinary maximum.

Every `allowedMobIds` entry needs a positive matching key in `threatCosts`. Spent budget is not
recycled when a mob dies, preventing infinite reinforcement loops.

### `vanilla.tactical`

This section controls formation radii, candidate limits, path attempts, replanning interval, target
movement required for replanning, and simultaneous melee attackers. Roles and orders continue using
vanilla navigation and attacks. The limits prevent large hordes from recalculating every route in the
same tick.

### `vanilla.multiplayer`

- `groupRadius`: distance at which players share an encounter context.
- `additionalPlayerScale`: extra encounter pressure per nearby eligible player.
- `maxGroupMultiplier`: hard cap on multiplayer scaling.

The model uses diminishing returns so three or four players do not trivialize an encounter without
creating an absurd linear mob multiplier.

### `vanilla.targeting`

These are the maximum ranges at threat 100 for skeletons, zombies, and generic `Monster` mobs in
Normal and Hard. Actual range interpolates upward only after `activationThreat`, protecting new or
underdeveloped players. When a family's Modded section is active, its family-specific range takes
priority.

### `vanilla.pressure`

This section exposes the full encounter curve that was previously hard-coded:

- Easy, Normal, and Hard base difficulty hazard;
- night, darkness, and cave hazard;
- contextual threat span;
- population fractions and environmental growth;
- minimum horde and melee fractions;
- reinforcement minimum, fraction, waves, and interval;
- tactical cadence and cooldown multipliers;
- separate ordinary Hard and Blood Moon profiles.

Easy automatic encounter chance remains zero. Normal applies partial pressure. Ordinary Hard uses
the reduced 2.0 curve. Blood Moon restores the full apocalypse profile.

### `vanilla.breachSimulation`

This is an OP diagnostic tool only. `enabled` controls the command; ray distance, block count,
hardness, and spawn radius constrain the plan. Simulation never changes blocks. The same spawn
protection radius also guards real destructive Modded abilities.

## 3. `modded`

`modded.enabled` disables every extraordinary feature below as a group. Each subsection has its own
`enabled`, and each major ability has a separate toggle.

### `modded.hud`

- `enabled`: permits synchronization and rendering.
- `operatorsSeeByDefault`: automatically shows the bar to OPs with the client mod.
- `allowCommandOptIn`: allows per-player visibility changes through commands.

The server checks channel support before sending HUD data. An unmodded client receives nothing and
is not disconnected.

### `modded.awareness`

Movement, sound, and light senses roll independently when a hostile mob is first assigned a profile.
Normal and Hard have separate probabilities.

Movement settings cover walking range, sprinting range, sneak reduction, and minimum speed. Light
settings cover minimum block light, base range, and range gained per light level.

Sound uses real server GameEvents:

- mining: `block_destroy`;
- explosions: `explode`;
- doors: `block_open` and `block_close`;
- containers: `container_open` and `container_close`;
- combat: `entity_damage`, `entity_die`, and `projectile_shoot`.

Each family has an audible range, player-attribution radius, and memory lifetime. An unattributed
sound only creates an investigation position; it does not grant omniscient player knowledge.

Detection values affect existing mobs that already own the sense. Assignment chance changes affect
new or previously unassigned mobs. Persisted entities are never rerolled by reloading the file.

### `modded.traits`

Independent toggles control `COWARD`, `BERSERKER`, `LEADER`, `REGENERATIVE`, `SWIFT`, and
`RESILIENT`. Normal and Hard profiles configure:

- first, second, and third trait probability and maximum traits;
- coward health thresholds and flee speed;
- berserker threshold, damage, and speed;
- regeneration interval and amount;
- leader interval, radius, and maximum allies;
- Swift speed, Resilient armor/knockback resistance, and particle cadence.

Trait combinations are deterministic and persistent. Disabling a trait makes its behavior inert;
new probabilities apply to newly assigned mobs.

### `modded.bloodMoon`

`minimumIntervalNights` and `maximumIntervalNights` define deterministic spacing between events.
`announceOmens`, `preventSleeping`, `nightStartTick`, and `omenMessages` control presentation and
sleep behavior. The current scheduled event persists; changed intervals govern future scheduling.

### `modded.skeleton`

Separate toggles control predictive aim, homing, status-effect arrows, and retreat dashes. Values
cover Normal, Hard, and Blood Moon range; attack interval; effect chance; minimum, mean, and maximum
duration; homing strength; dash velocity; and cooldown bounds.

### `modded.zombie`

Separate toggles control equipment, shield blocking, sticky aggro, nearby alerts, lightning hordes,
reinforcements, and block breaking. Each difficulty tier controls equipment chance, tool choices,
pickaxe and shield rarity, shield block chance, reinforcement caps, and mining cooldown.

Additional values cover target range, axe shield-disable duration, horde chance at activation and
maximum threat, nearby alert radius, and horde size per tier.

Block breaking requires a suitable tool, `mobGriefing`, loaded safe blocks, world-border access,
spawn protection, and claim permission. It produces no drops to prevent automated resource farms.

### `modded.spider`

Independent toggles control status buffs, on-hit cobwebs, and death hatchlings. Tier settings expose
effect amplifiers, web cooldown, hatchling count, and hatchling chance. Ordinary and Blood Moon web
probabilities have separate activation and maximum-threat values.

### `modded.creeper`

Independent toggles control silent steps, rear pursuit, randomized fuse, dash, and coordinated
breaching. Values expose ordinary and Blood Moon speed/fuse profiles, target memory, dash impulse and
cap, breach distance, wall hardness, assignment lifetime, and fuse delay.

The coordinator reserves one nearby creeper for a viable route-opening wall. Real explosions still
respect `mobGriefing`, spawn protection, chunks, the world border, and claims.

### `modded.enderman`

Independent toggles control allied retaliation, the two-block combat posture, and anti-pillar
teleporting. Each tier exposes alert radius, ally count, chance, pillar confirmation time, and
teleport cooldown.

### `modded.drowned`

Independent toggles control night swim speed, tridents, Riptide, and boat breaking. Normal, Hard, and
Blood Moon profiles expose speed multiplier, trident/Riptide chance, enchantment level, dash speed,
cooldown, target range, and boat-breaking permission.

Equipment and enchantments roll at spawn. Movement and targeting respond dynamically.

### `modded.otherHostiles`

Family toggles cover witches and raiders, aerial fire mobs, guardians, drowned and husks, swarms,
and brutes. Normal, Hard, and Blood Moon ranges control generic family targeting. These bounded rules
do not replace AI installed by other mods.

## Reload behavior


| Change type                                                                                    | When it takes effect                                                                             |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Master toggles, active chances, cooldowns, dynamic ranges, caps, messages, HUD, and OP logging | Immediately after a successful reload                                                            |
| Awareness, Traits, and spawn equipment assignment                                              | New or newly materialized mobs; persistent entities are not rerolled                             |
| Increasing the initial target-predicate maximum for an already loaded mob                      | Guaranteed for mobs loaded after the change; dynamic checks still enforce reductions immediately |
| Disk telemetry and integrations                                                                | Server restart                                                                                   |
| Blood Moon interval                                                                            | When the next event is scheduled; the current persisted event is not rewritten                   |




## Migration and recovery

When upgrading from schema 3:

1. The old `config/threatdirector.json` remains intact.
2. Compatible values migrate into `general` and `vanilla`.
3. New 2.x features receive safe defaults in `modded`.
4. Threat Director writes a fully documented `config/threatdirector.json5`.

JSON5 becomes authoritative after creation. To regenerate defaults, stop the server, move the JSON5
file to a backup location, and start again.

## Recommended diagnostics

```text
/threatdirector debug config reload
/threatdirector threat
/threatdirector logging on
/threatdirector debug status
```

If a session feels too intense, adjust `activationThreat`, ranges, and chances before raising
performance limits. If it feels inactive, confirm the three master switches, the relevant feature
toggle, Minecraft difficulty, and whether the player has passed the activation threshold.
